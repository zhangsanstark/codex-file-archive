## 后续上传规则

- 使用上传当天的日期；自 2026-09-15 起，新批次目录使用 `001/`、`002/`、`003/`……三位补零数字编号，当天继续递增，新日期从 `001/` 开始；历史中文批次目录保留。
- 一个上传请求对应一个批次；单个文件夹的内容直接放入批次内。一次上传多个独立文件夹时，在批次内保留各文件夹名称。
- 自 2026-09-14 第五次起，所有新上传文件使用“内容的完整 SHA-256 哈希＋原扩展名”，文件名不含内容主题；粘贴文字保存为 UTF-8（无 BOM、LF 换行）的 `.md` 文件后计算哈希。保留正文及目录层级，不追溯修改历史文件名。
- 新批次的索引使用通用材料类型或哈希，不再写具体内容标题；历史索引保留。
- 已有批次保留；新增材料或修改版通常形成新批次。用户明确指定更新旧文件时按要求处理。
- 每次新上传同步更新本索引。目录整理本身不计入新的材料上传批次。
- 历史材料按原上传顺序重新整理，正文保持不变；旧路径可在整理前的 Git 提交中查看。
