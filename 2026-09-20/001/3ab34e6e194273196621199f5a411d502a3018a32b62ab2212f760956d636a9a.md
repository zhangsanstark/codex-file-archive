# 风控可主导的版权与相关权益方案

讨论稿 v1，2026-09-20。范围经用户确认：规则、Skill、审核服务、版权库和评测。以下均为设计建议，尚未实施或验证，不构成上线、效果或排期承诺。现有 PPT 保持不变。

**用途更新：** 本文作为技术措施备选清单。当前按用户要求以 [版权风险安全对齐与审核整体方案](07_版权风险安全对齐与审核整体方案.md)为讨论主线，不将以下措施当作需要逐个选痛点立项的并列项目。

## 我的建议

建议以**可配置的意图审核、连续输出的放行控制、图片上下文复核**作为能力建设主线，用**可追溯的版权库和统一评测**支撑它们。重点不是继续堆叠拒答规则，而是明确识别什么、由谁决策、何时放行，以及误拦后如何继续完成用户任务。

先进行一次现有链路覆盖核验和基线评测，再决定投入比例。若发现审核前已展示、长文或跨段未覆盖，应先补齐；若覆盖完整，则把主要增量投入放在意图误判、库外原文索取和图片关键词误拦。不能仅根据默认 512 tokens 的材料认定现网存在缺口。

## 方案 A：Skill 识别请求，策略服务执行规则

**解决的问题：** 纯关键词只看名称；让大模型直接自由判断“是否侵权”，又难以统一地域、授权和例外规则。用户的一句“我是作者”也不能成为可信授权依据。

**与现有能力的衔接：** 保留正在建设的输入 Skill，目标是让它返回结构化信息，交给可版本化的规则服务处理。当前材料并未确认 Skill 能否独立调用、强制执行或返回结构化结果：若仅能注入指令，先做规则表达、替代回复与离线评测；具备审核接口后再接策略服务。输出侧仍由现有匹配链路审核。

建议 Skill 识别五类信息：

1. 对象：作品、版本、角色或人物的候选标识，允许“不确定/未识别”。
2. 操作：原文提取、续接、翻译/改写、摘要分析、用户材料处理、图像创作或参考图编辑。
3. 来源关联：依据服务端传入的已上传文本范围、检索片段等事实，判断是否要求系统补全未提供内容。来源事实由服务端提供，不能由用户自述或模型猜测代替。
4. 上下文：本会话是否已持续提取同一对象，当前是否转向正常讨论。
5. 判断依据及不确定性：可以复核的短理由，而非要求暴露模型内部推理过程。

地域、已核验授权、组织权限和规则版本由业务系统提供。Skill 不能根据用户文本自行改变这些可信状态。策略服务输出明确动作，如正常处理、限制引用、摘要替代、拒绝受限部分、待复核。

**关键增量：** 对“库里没有的作品”，也能识别明显的受限原文提取意图；对“库里有的作品”，也能保留正常摘要、评论及经核验授权的路径。库未命中不再被误解为版权状态已确认。

**实现取舍：** 第一版不必训练新模型，可先以受控 Skill 加规则服务实现。是否增加独立审核模型，应由同一测试集上的一致性、延迟和成本决定。同一个模型负责生成及自审可能共享盲区，因此不能只看自审是否同意自己。

**依赖：** 风控定义任务分类与结构化输出；法务审核处置矩阵；研发提供可信业务字段和失败处理。风控可主导，但不代表完全不需要研发接入。

**验证：** 同一任务切换作品、授权状态、地区和话术，检查策略一致性；重点测试“索取原文”与“讨论原作”、“提供原文做处理”与“要求补全未提供部分”。统计正常任务误拦和实际受限内容释放，不能只统计拒答率。

**优先级：** 近期主线。规则先小范围固化，保留回滚；不将法务未确定的情境交给模型自行定性。

## 方案 B：审核覆盖到全文、跨段与用户实际接收

**解决的问题：** 一个回答最终被检出，不代表此前没有展示风险片段。单轮、单段匹配也不直接回答同一作品是否被连续提取。

**与现有能力的衔接：** 优先在现有指纹与连续匹配服务外补充状态管理，而非立即替换引擎。

- 全文覆盖：记录已审核范围，核验长回答尾段、段间衔接、流式结束、取消和重试。
- 分段衔接：按现有匹配阈值与容错要求设计重叠或增量状态，不能用一个未经验证的固定窗口代替证明。
- 展示控制：区分“已生成”“已审核”“已发送”三种状态。所有输出保留既有匹配审核作为最低要求，并核验是否能在释放前执行；风险分级只决定额外缓冲或深度复核强度，不能让输入漏判绕过输出检查。不能把事后撤回当作用户从未收到。
- 会话状态：先在同一会话中，按作品记录已经释放的匹配片段及顺序，去重后评估累计提取。重复引用同一句与连续获取新段落应区别对待。
- 正常任务恢复：发现分批索取后限制继续提取，仍允许转向摘要、主题和知识性讨论。避免永久封锁关于该作品的一切问题。

**关键增量：** 将“单次输出检出率”推进到“会话中实际释放的受限内容是否可控”。跨账号、跨设备累积涉及不同的识别与隐私问题，不列入第一阶段。

**成本取舍：** 缓冲与复核会增加等待，尤其是长文。应比较小块缓冲、按风险分流和整段审核，统一衡量用户可见泄漏及额外延迟。通用流式安全模型可作为试点工具，不能代替版权证据或放行协议。

**依赖：** 风控主导审核标准和验收；生成网关或流式返回层改造单列研发接入依赖。还需稳定作品 ID、可复核的匹配位置、会话状态过期机制和最小化记录。

**验证：** 将受控测试片段放到开头、长文末尾、窗口交界和多轮中，观察最终展示内容。异常场景包括服务超时、最后一段、重试和客户端取消。审核服务不可用时采用哪种降级方式须预先配置，避免默认绕过。

**优先级：** 立即核验。有缺口则优先修复，无缺口则沉淀覆盖证明后做会话增强。

## 方案 C：图片由“识别名字”提升为“理解请求并复核成图”

**解决的问题：** 关键词会漏掉指代、拼音和间接描述，也会阻断正常讨论、泛化创意或并未要求复制角色的请求。输出模型能补充输入漏检，但无法挽回已经发生的输入误拦。

**与现有能力的衔接：** 保留已完成的关键词、IP 审核和人脸名单匹配。先离线评测或影子运行新的图文上下文审核，架构支持后再进入在线流程。

建议形成两类输入路径：

- 明确的紧急硬性管控规则直接执行，支持到期复核与回滚。
- 含混的名称或风格请求交给上下文识别，区分具体角色复现、普通属性、讨论性任务及参考图编辑；输出仍必须经过现有两路审核。

输出侧对少量含混结果提供按需复核：结合原始请求、生成图、候选 IP 参照或人物命中证据，形成“哪些具体特征触发策略”的判断。通用多模态模型可提供辅助意见，但不凭自报置信度直接推翻高置信度命中。

**关键增量：** 将新增模型集中到现有系统最容易误判的样本，争取降低关键词误拦和模糊描述漏拦。先证明增量，不要求所有图片都额外调用大模型。

**处置建议：** 受限请求提供保留通用属性的替代创意，如保留“黄色、活泼、卡通猫”等普通需求，同时剔除需管控的具体角色特征。不能仅删角色名就视为完成替代。自动重新生成需要次数和成本上限，每次结果都复审；不能满足任务时给清楚提示。

公众人物匹配继续单列权益策略。身份相似度不是侵权结论，按名单、场景和已核验授权处理，不改变当前已确定的强制管控要求。

**依赖：** 图文审核接入能力、清晰的 IP 参照与人物策略、具有正常近似样本的标注集。若当前架构不能传图文联合上下文，可先做离线复核与数据积累。

**验证：** 以现有输入命中与输出误判样本做成对比较，同时独立抽样未命中请求，避免只看旧系统已发现的问题。考察误拦下降和新增放行风险，预先确定哪些规则允许复核调整、由谁批准。测试具体形象复制、变形描述、仅共享通用属性、参考图改绘、小面积角色及多人物场景。参考素材业务是否存在尚待确认。

**优先级：** 可先启动离线验证，在线试点受架构条件约束。不能写成已经完成的增强能力。

## 方案 D：版权库增加权利与适用策略，扩库按风险排优先级

**解决的问题：** 仅有作品内容或关键词，难以回答“哪一版本、哪些区域、何种用途需要限制”，也难以支撑授权例外。盲目扩库容易增加维护成本，而不知覆盖了哪些真实风险。

**与现有能力的衔接：** 在现有 300+ 本书、2,000+ 首歌曲和 IP/人物名单上做增量字段，不要求先建一个庞大的统一平台。

建议试点字段包括：对象 ID 与别名、内容版本、权利类型、参考素材来源、地域、授权范围与期限、规则依据和负责人、策略版本、变更记录。作品库与人物库可以共享策略接口，但其权利类型、数据权限和处置规则应分开。

优先入库对象由“确认的投诉、请求热度、业务暴露、现有覆盖不足”共同决定。临时应急规则有复核和到期状态，确认后的案例再沉淀为正式规则及回归样本。

**关键增量：** 将命中证据和可信的权利状态连接起来，既能精准拦截，也能支持已获许可的服务。用户自称授权不直接放行，模型推测作品已进入公版也不直接进入白名单。原著与译本、改编和不同地区的状态可能不同。

**成本取舍：** 难点主要在证据核验和持续维护，法务/版权商务提供结论，风控负责可执行化。不建议第一阶段承诺查清所有互联网作品。

**验证：** 对授权到期、地域切换、用途不符、译本与原著、应急规则撤销等场景做固定回归；检查同一策略能否同时作用于输入 Skill 和输出命中处置。

**优先级：** 与 A 并行小范围建设。大规模授权采购和训练数据清理不在本轮风控交付范围。

## 方案 E：对重点作品试点“语义召回＋具体表达复核”

**解决的问题：** 连续文本匹配对翻译、较大改写或表达顺序变化可能缺少覆盖，但单纯提高语义相似阈值又容易误伤摘要、同题材内容和正常评论。

**与现有能力的衔接：** 指纹匹配保留为低成本、高解释性的主要证据链。先对已确认漏检样本做离线候选召回与人工复核，证明增量价值后，再决定是否建设在线向量服务。在线候选方案针对高风险请求或重点作品中未命中的样本召回片段，再核对表达细节、顺序、内容量和用途。

**关键增量：** 识别现有链路中真实存在的语义复现缺口，同时限定额外算力与误拦范围。没有参照作品时只能给风险提示或意图判断，不伪造对应原文和证据。

**成本取舍：** 增加向量检索与复核调用、参照库加工、疑难样本标注。概念相近、人物相同或主题一致不能单独作为拦截依据。应先影子评测，复核质量不足时不进入自动拦截。

**验证：** 测试集必须配对包含逐句译写、表达细节复现，以及正常梗概、批评分析、同主题原创。分别统计候选召回率、复核正确率、最终新增检出/误拦和每千请求额外调用量，以定位筛选、召回及处置各环节的问题。不把 CopyBench 等研究中的非字面相似指标直接等同法律侵权。

**优先级：** 第二阶段小范围探索。若基线未显示明显缺口，不宜在全量流量中先加昂贵语义审核。

## 方案 F：建立能决定上线的评测和反馈闭环

**解决的问题：** 当前 98.46% / 0% 只能说明已给测试样本的结果，尚不足以推断系统整体能力，更不能回答每次新增规则是否改善用户体验。

风控可以主导以下工作：固定标注规范、建立正常请求难负例、区分库内外与地区语种、建立会话级测试和用户可见输出记录。投诉经核验后进入作品库或规则库，同时生成回归用例；误拦经复核后也进入正常样本集。

评测要分别呈现识别、处置和交付三个环节。输入拒答但替代内容泄漏、输出检出但已经展示、完全拒绝正常任务，都不能算完整成功。对模型、Skill、版权库和规则版本保存同一组测试记录。

**关键增量：** 后续每个投入都能回答具体改善了什么，而非用新增规则数量、库大小或拒答率替代效果。

**成本取舍：** 需要持续标注及法务裁决少量边界样本。可以优先集中高频和高风险场景，保留独立盲测，不把调优样本反复当验收样本。

**依赖：** 现有日志、工单与发布流程接入，明确素材使用权限、存储期限及审核权限。

**验证与交付：** 见 [评测与验证设计](06_评测与验证设计.md)。具体目标值应根据基线、样本量和风险承受范围协商，当前不编造统一门槛。

**优先级：** 作为所有试点的共同基础同步启动，不必等所有能力完成。

## 推荐推进组合

| 阶段 | 建议交付 | 为什么这样排 |
|---|---|---|
| 先建立基线 | B 的链路覆盖核验 + F 的专项评测 + D 的小范围规则清单 | 避免把现有问题猜错，也让后续投入可以比较 |
| 近期能力主线 | A 的结构化 Skill 与分级处置；有覆盖缺口时同步补 B | 最直接利用已在建设的能力，且能由风控推动 |
| 图片专项试点 | C 的离线/影子评测，架构支持后进入在线 | 已有图片检测，不重复宣称“建设图片审核”，重点验证误拦与漏拦增量 |
| 按证据追加 | E 的重点作品语义复核，以及更多授权状态/对象覆盖 | 投入相对高、边界更难，应以真实风险和评测结果驱动 |

这不是固定排期。若当前最大痛点是图片关键词误拦，可将 C 提前；若已发现长文/流式实际释放问题，则 B 优先于新增模型。

## 本轮不作为主项目的方向

训练数据去重、SFT/RL、安全训练、机器遗忘、许可采购和对外赔偿承诺都需要其他团队主导或深度参与。可在长期路线中保留，但不以它们充当风控近期可交付成果。生成标识和来源凭证可辅助追溯，也不替代版权审核或授权证明。
