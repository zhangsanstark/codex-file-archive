# 版权风险安全对齐与审核整体方案

讨论稿 v2，2026-09-20。根据用户最新要求，本方案从模型安全中的版权风险治理出发，构建完整体系，不再以选择某一个痛点作为讨论前提。此前竞品调研作为依据，单点候选方案作为实施参考。当前不修改 PPT。

## 一、定位与目标

对于具备文本、图片等内容生成能力的通用模型，版权风险是一项共性治理课题。风险形态和程度受模型能力、内容来源、使用方式、产品功能及适用规则影响，不能断言每个模型有相同风险或已经发生侵权。

建议将目标定义为：**使模型能够理解并遵循版权使用边界，系统能够审核和控制实际输出，同时保留正常的信息获取、分析与创作能力。**

整体体系有两部分共同工作：

- **模型行为对齐：** 让模型在生成过程中正确区分受限复现与正常任务，面对规避请求保持规则一致性，并在需要限制时提供有用的替代帮助。
- **系统审核与执行：** 独立检查请求和实际输出，依据可信的权利信息与产品规则决定处置，并确保审核约束作用于用户实际获得的内容。

输入 Skill 是运行时行为约束的一种实现。通过训练改变模型行为，需要模型团队使用风控提供的规则、样本及评测开展训练和验证。两种方式可以协同，但不能把加载 Skill 直接描述为已经完成模型内生安全对齐。

## 二、统一的规则和权利依据

由风控与法务共同维护一套版权规则，供输入审核、模型行为约束、输出处置和评测共同使用。模型和审核组件可以不同，规则应有共同版本和可追溯依据。

规则需要回答以下问题：

| 判断维度 | 需要明确的内容 |
|---|---|
| 对象 | 书籍、歌词、文章、具体图片作品、IP 形象等；公众人物相关权益另列策略 |
| 用户行为 | 索取原文、续接、翻译或改写、摘要评论、用户材料处理、生成图片、参考图编辑等 |
| 内容来源 | 模型生成、用户实际提供、检索/联网取得、已核验的授权内容 |
| 权利与业务条件 | 作品版本、地域、授权用途及期限、已核验的公版状态、适用例外与业务管控要求 |
| 会话上下文 | 是否持续索取同一作品、已经向用户释放了哪些内容、是否转回正常任务 |
| 处置动作 | 正常响应、按条件响应、替代帮助、拒绝受限部分、复核与纠错 |

规则是对法律和业务要求的可执行表达，不能让模型临时发明。地域和授权等可信状态由业务系统或经核验台账提供；用户自称拥有版权不自动改变状态。字数、行数和匹配长度可用作内部控制参数，但不作为通用法律安全线。

版权库也承担支撑作用：作品 ID、别名、版本、参照内容、权利信息和处置策略相互关联。匹配命中提供事实证据，策略判断决定在具体场景中如何使用该证据。已经获准的用途与受限用途可以对应不同动作，避免将所有入库作品都理解为一概不可讨论。

## 三、一次请求如何经过完整链路

| 环节 | 核心职责 | 如何与下一环节衔接 |
|---|---|---|
| 1. 请求与上下文接入 | 接收 query、必要会话信息、用户材料范围和可信业务条件 | 保留真实来源信息和请求对象，供后续判断使用 |
| 2. 输入风险识别与策略判断 | 识别用户要完成的任务、目标作品/人物、受限提取及规避意图；执行关键词应急规则 | 决定允许的回答方式，向生成模型传入相应约束，明确拒绝受限部分时可提供何种帮助 |
| 3. 按规则生成 | 模型执行版权行为规范，正常完成允许任务，必要时转向摘要、分析等替代帮助 | 生成内容进入输出审核，包含替代回答和重新生成的内容 |
| 4. 输出证据检测 | 文本进行作品匹配与连续复现检测；图片进行 IP 识别、人物匹配及必要的语境复核 | 返回风险类型、作品/人物候选、命中证据和不确定性，交策略判断 |
| 5. 统一处置与交付 | 综合规则、权利条件、请求意图和实际内容，执行放行、限制、替代或拦截 | 审核约束作用于最终展示；对长文、分段、流式及其他实际出口核验覆盖 |
| 6. 会话状态更新 | 记录必要的对象、已释放范围和处置结果 | 下一轮可以识别连续提取，同时允许用户转回正常讨论 |

输入端和输出端调用同一套规则逻辑，分别解决“允许如何回答”和“这次实际内容能否交付”。输入判断通过后，输出审核仍然有效；输出未匹配到已知作品，也不代表系统已证明作品不存在或内容获得授权。

审核组件出现超时、不可用、状态冲突或不确定结果时，需要有预先定义的降级策略。不能由调用失败静默变成直接放行，也不宜把所有异常统一转成对所有任务的永久拒绝。

## 四、模型应该具备的版权安全行为

这一部分是安全对齐的目标规范，也是 Skill、训练样本和评测的共同依据。

| 能力 | 期望行为 |
|---|---|
| 理解使用边界 | 区分对作品的正常讨论与对受限表达的提取，结合来源和可信授权条件处理 |
| 识别受限索取 | 识别全文、章节、歌词、指定位置、续接及可能替代原作的复现请求 |
| 保持会话一致性 | 识别分批提取、改换说法或语言等连续请求；限制继续提取后仍能恢复正常分析 |
| 保留正常服务 | 对允许的摘要、评论、知识问答和创作正常作答，不因出现作品名或角色名就机械拒答 |
| 提供有效替代 | 对受限部分作简洁说明，提供符合规则的摘要、分析或经核验来源指引，避免借替代之名恢复原文 |
| 正确处理图像意图 | 区分具体受限形象与通用视觉属性，结合输入材料及最终成图适用规则 |
| 面对不确定性 | 不编造版权归属、授权、公版状态或原文内容，按明确的保守处置或复核规则处理 |

**实现方式分层推进：** 风控先提供统一规则、正反例、受控回复规范和专项评测。运行时可通过系统指令、Skill 或独立审核调用应用这些规则；具备模型团队协作条件时，再将经核验样本用于后训练或其他行为优化，并沿用同一验收标准。模型行为提升后，独立输出审核仍是体系的一部分。

风控可主导规则和验收，不需要承担训练执行。但总体设计应保留向模型团队反馈的接口，避免长期只增加外部拦截而不改善生成行为。

## 五、文本与图片使用同一套框架，采用不同检测方式

### 文本版权

输入侧理解索取意图与上下文，输出侧检查实际生成内容。现有连续/近似匹配能够提供作品与位置证据，应继续保留。版权库未覆盖的对象，由意图规则和必要复核补充风险控制，但不伪造匹配证据。

对长回答、分段与流式输出，审核需要与交付协议衔接。对同一作品的连续会话，既看本次内容，也看已经释放的相关片段。语义召回可作为重点作品的增强手段，需要验证是否能区分表达复现、正常梗概及同主题创作。

### 图片版权与公众人物相关权益

输入关键词继续承担明确规则与快速应急，语义识别补充请求的真实意图。生成后继续使用已完成的 IP 审核和人脸名单匹配，必要时结合 query、参考图与生成结果进行复核。

公众人物身份匹配属于相关权益风险信号。是否限制及如何限制，依据独立的名单、用途和授权策略，不与图片作品版权混同。通用风格或颜色相近也不能单独替代具体作品/IP 的识别证据。

图片意图能力在现有架构支持前，可以先完成规则、样本和离线验证。当前图像 IP 与人物审核已构建完成，这些既有能力应准确列在现状中。

## 六、完整的处置能力

体系应支持不同结果，而不是只有一个拒答模板。

| 策略结果 | 用户侧行为 | 系统要求 |
|---|---|---|
| 正常响应 | 完成允许的问答、分析或创作 | 生成结果仍按要求审核 |
| 按条件响应 | 在已确认的引用、授权、地域或用途边界内完成任务 | 不将出处标注或用户声明作为自动授权 |
| 替代帮助 | 受限原文转为摘要/分析，受限具体形象转为符合规则的通用创意 | 替代内容自身再次审核，保留用户可完成的任务 |
| 拒绝受限部分 | 清楚说明不能提供的内容，避免不必要地终止整项任务 | 固定处置原因和策略版本，限制重复失败生成 |
| 待复核与纠错 | 对疑难权利或误拦提供适当的反馈渠道 | 支持人工核验、规则修正和回归验证，不承诺实时人工审查所有请求 |

自动重试或重新生成应有上限。已经展示的内容无法通过后台撤回保证用户从未接收，因此“审核后交付”与“事后处置”需要分开记录。

## 七、如何让体系持续有效

建立一套同时验收模型行为和系统整体效果的版权专项评测。

**模型行为评测**关注：能否理解受限请求、能否保留正常使用、能否抵抗规避、替代帮助是否有效。对运行时 Skill 和经过训练的模型使用可比较的任务定义，同时注明测试配置。

**端到端评测**关注：最终用户实际收到什么，长文和多轮是否受控，正常请求是否被误拦，增加审核后延迟和成本如何变化。输入拦截率或单个模型准确率都不能独立代表整体效果。

测试集应同时包括直接原文索取、多轮与变形请求、正常摘要评论、用户材料处理、经核验的授权/公版场景，以及图片具体形象与普通属性的边界。作品、语种、地域、内容类型和模型版本分层记录，开发集与独立验收集分开。

所有规则、模型、版权库和服务更新都应有对应评测记录。经核验的投诉与误拦反馈进入规则、样本或版权库，再运行回归；能通过行为训练改善的问题，同时反馈模型团队。重复投诉处理与申诉纠错共用证据记录，避免临时策略一直累积而无人复核。

详细指标设计见 [评测与验证设计](06_评测与验证设计.md)。当前 98.46% 检出率和 0% 误检率仍按用户给定测试口径保留，待补充样本量、分母和范围，不扩写为全体系效果。

## 八、数据与团队分工

建议维护三类基础资料，并用稳定 ID 和版本关联：

| 基础资料 | 内容 | 主要责任 |
|---|---|---|
| 规则与权利资料 | 版权处置规则、对象版本、授权范围、地域、期限和依据 | 风控制定执行规则，法务审核边界，版权/业务团队提供有效证明 |
| 参照与审核证据 | 书籍歌词指纹、IP 参照、人物策略名单、命中位置及必要事件记录 | 风控及审核研发维护，设定来源、权限和存储要求 |
| 对齐与评测资料 | 正反例、合规回复、规避样本、固定回归、独立验收及投诉纠错用例 | 风控主导标注规范及验收，模型团队消费适合训练的数据并反馈结果 |

生成和网关团队负责将规则、审核调用及交付约束接入真实产品。模型团队负责训练层面的行为提升。法务负责法律适用、授权和边界判断。风控负责把要求组织成可执行、可验证、可迭代的整体方案。

训练数据合法来源、获取许可及数据使用治理是相关责任线，应由法务、数据与模型团队协作管理。生成输出审核的结果不能替代训练数据合规证明。本方案核心覆盖生成服务的版权安全对齐与审核，同时保留这一依赖关系。

## 九、现有能力在体系中的位置

| 模块 | 当前已知状态 | 整体规划中的下一步 |
|---|---|---|
| 文本输出连续匹配 | 已具备；300+ 本高风险书籍、2,000+ 首歌曲 | 继续提供证据，纳入统一处置及全输出覆盖验证 |
| 文本输入 Skill | 风控与法务共建中 | 使用统一行为规范，明确运行时接入方式并建立正反例评测 |
| 图片关键词与应急词库 | 已构建 | 保留应急能力，与意图及权利规则协同 |
| 图片 IP 审核 | 已构建 | 纳入统一处置，结合真实样本验证含混结果的复核 |
| 公众人物匹配 | 已构建 | 在整体链路中单列相关权益策略及验收 |
| 图片意图理解 | 待架构支持后探索 | 先准备规则和评测样本，具备条件后接入 |
| 权利台账、会话状态、交付覆盖、整体评测 | 当前材料不足以确认完整建设情况 | 核验可复用能力后补齐，不默认现网缺失 |
| 训练层版权行为优化 | 尚未提供建设状态 | 风控输出规则/样本/验收要求，由模型团队评估接入 |

## 十、整体建设的可验收成果

未来规划可以围绕一套完整交付描述：

1. **形成版权行为与处置规范。** 输入识别、生成约束、输出判断和评测使用一致的规则与版本。
2. **打通文本和图片审核链路。** 复用现有检测，补充必要意图与语境能力，明确全部实际出口的交付要求。
3. **建立持续对齐与迭代机制。** 版权库、训练/Skill 样本、专项评测和反馈相互连接，迭代同时考察风险控制与正常使用效果。

这三项描述的是同一体系的建设成果，具体技术措施是实现选项。后续讨论围绕体系边界、职责和验收方式展开，再将确定内容压缩为领导汇报第三页。
