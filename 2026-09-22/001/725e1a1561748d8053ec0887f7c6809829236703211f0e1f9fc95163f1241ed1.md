**第 3 页｜文本版权整体审核流程**

这一页只展示主线，建议流程如下：

> 用户 Query → 是否加载 Skill → Skill 按规则发挥作用 → 大模型生成回复 → Answer 版权审核 → 返回用户 / 拦截

这里补清楚两个分支：

- **加载 Skill：**模型结合版权规则处理请求，再生成回复。
- **不加载 Skill：**直接进入大模型回复环节。
- **两条路径汇合后：**生成的回复统一进入 Answer 审核，通过后返回用户，命中风险则拦截。

版式采用横向流程图，突出输入侧和输出侧两个环节。Skill 具体加载条件留到下一页讲，这页不展开。

**第 4 页｜输入侧：Skill 版权意图识别**

这一页回答三个问题：**Skill 怎么起作用、管哪些请求、不同地域怎么配置。**

上部用一个简化模块说明：

> 用户请求与会话上下文 → 应用对应地域的 Skill 规则 → 识别请求意图 → 按规则回答

规则范围先概括为：

- 原文索取：全文、章节、指定片段等。
- 歌词索取：歌词及核心段落等。
- 续写与提取：指定位置续写、分批索取等。
- 规避请求：变形表达、翻译等场景，按具体规则判断。

地域策略建议这样表述：

| 国内策略海外策略                                |                                        |
| --------------------------------------- | -------------------------------------- |
| 结合业务风险与友商实践，构建重点作品管控清单，对清单内作品的受限请求实施拦截。 | 结合当地法律要求、作品权利状态及授权情况，构建适用规则，对受限请求实施拦截。 |

这里建议将“国内风险小、海外风险大”表达为**“不同地域采取差异化管控策略”**。海外也不直接写“有权利人的作品全部拦截”，以免把作品介绍、评论等正常请求包含进去。

**视觉重点放在你提供的两张前后对比图：**

- 同一请求，未加载 Skill 时的回复。
- 同一请求，加载 Skill 后的回复。

友商截图选取最有代表性的关键区域，放在地域策略旁边。这页内容较多，建议以两张效果对比图为主，友商截图作为辅助证据。
